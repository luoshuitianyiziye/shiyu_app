# 时屿 App 开源上手指南（小白版）

> 本文档手把手教你如何把「时屿」项目发布到 **Gitee（码云）** 和 **GitHub**，
> 全程零基础可跟做，每一步都有截图描述和命令。

## 一、先搞懂三件事

### 1. 开源是什么？

把你的代码放到公开的代码托管网站上，任何人都能看到、下载、学习，甚至帮你改进。
对程序员来说，开源作品就像"简历上的勋章"，非常加分。

### 2. 为什么同时发 Gitee 和 GitHub？

| 平台 | 特点 | 适合 |
|---|---|---|
| **Gitee（码云）** | 国内访问快，中文界面，国内开发者多 | 国内推广、给中文用户看 |
| **GitHub** | 全球最大，英文界面，国际影响力大 | 国际曝光、求职加分 |

两个平台都发，覆盖最全。**核心流程完全一样**，只是网址不同。

### 3. 你的签名密钥安全吗？（重要！）

你的 App 发布版需要一把"数字签名钥匙"（文件是 `shiyu-release.jks` 和 `key.properties`），
它放在 `android/` 目录下，**已经被 `.gitignore` 排除，绝不会随代码上传**。

> ✅ 我已经帮你检查过：`key.properties`、`*.jks`、数据库文件全部排除在外，
> 122 个待提交文件里没有任何密钥。你可以放心开源。

## 二、准备工作（只需要做一次）

### 第 1 步：注册账号

| 平台 | 网址 | 说明 |
|---|---|---|
| Gitee | https://gitee.com/signup | 手机号或邮箱注册 |
| GitHub | https://github.com/signup | 邮箱注册，需要验证邮箱 |

> 💡 GitHub 注册后建议开启**两步验证**（2FA），保护你的账号。

### 第 2 步：安装 Git（如果还没装）

打开终端（Windows 按 `Win + R`，输入 `cmd` 回车），输入：

```bash
git --version
```

- 如果显示 `git version 2.48.1...` 之类 → 已安装，跳过
- 如果提示"不是内部或外部命令" → 去 https://git-scm.com/download/win 下载安装，
  一路点"下一步"即可（默认选项都行）

### 第 3 步：设置你的身份（提交代码时显示的名字）

```bash
git config --global user.name "你的名字或昵称"
git config --global user.email "你的邮箱"
```

> 比如：`git config --global user.name "shiyu"`，`git config --global user.email "you@example.com"`

## 三、把代码推送到 Gitee（先做这个，国内快）

### 第 1 步：在 Gitee 上创建空仓库

1. 登录 Gitee → 点右上角 **+** 号 → **新建仓库**
2. 填写：
   - **仓库名称**：`shiyu_app`（或你喜欢的名字）
   - **路径**：自动生成，不用改
   - **简介**：时屿 · 日程笔记 —— 养成系效率 App
   - **是否开源**：选择 **公开**（开源必须公开）
   - **初始化仓库**：⚠️ **全部不要勾选**（不要加 README、不要加 .gitignore、不要加许可证，我们本地都有）
3. 点 **创建**

### 第 2 步：拿到仓库地址

创建成功后，页面上会显示一个地址，形如：

```
https://gitee.com/你的用户名/shiyu_app.git
```

**复制这个地址**，下一步要用。

### 第 3 步：添加远程地址并推送

打开终端，进入项目目录：

```bash
cd D:\project\deepseekcoding\Notebookproject\shiyu_app
```

把仓库地址告诉 Git（把 `你的用户名` 换成你自己的）：

```bash
git remote add gitee https://gitee.com/你的用户名/shiyu_app.git
```

推送代码（`-u` 是第一次关联，以后就不用带了）：

```bash
git push -u gitee master
```

> 💡 如果分支名不是 master 而是 main，就换成 `git push -u gitee main`。
> 可以用 `git branch` 查看当前分支名。

### 第 4 步：输入账号密码

第一次推送会弹窗要求登录，**两种方式任选**：

- **方式 A（推荐）**：浏览器会自动打开，网页上登录一次，Git 会记住凭据
- **方式 B**：手动输入——用户名填你的 Gitee 用户名，
  密码**不是登录密码**，而是**私人令牌**（见下方"常见问题 Q3"）

看到 `master -> master` 和 `done` 字样，就成功了！

**现在去 Gitee 刷新你的仓库页面，就能看到代码了。** 🎉

## 四、把代码推送到 GitHub

流程和 Gitee 几乎一样，只是地址不同。

### 第 1 步：在 GitHub 创建空仓库

1. 登录 GitHub → 点右上角 **+** → **New repository**
2. 填写：
   - **Repository name**：`shiyu_app`
   - **Description**：时屿 · 日程笔记 —— 养成系效率 App
   - **Public**：选中（开源必须公开）
   - **Add a README / .gitignore / license**：⚠️ **全部不要勾选**
3. 点 **Create repository**

### 第 2 步：添加远程地址并推送

```bash
cd D:\project\deepseekcoding\Notebookproject\shiyu_app
git remote add github https://github.com/你的用户名/shiyu_app.git
git push -u github master
```

GitHub 同样会要求登录（浏览器授权或输用户名 + 令牌，令牌生成方法见 Q3）。

看到 `done` 就成功了，刷新 GitHub 页面确认。🎉

## 五、以后更新代码（日常操作）

以后你改了代码想同步到网上，只需要三步：

```bash
cd D:\project\deepseekcoding\Notebookproject\shiyu_app
git add -A
git commit -m "描述这次改了什么"
git push gitee master
git push github master
```

> 💡 也可以设置"一个命令推两个平台"：
>
> ```bash
> git remote set-url --add --push gitee https://gitee.com/你的用户名/shiyu_app.git
> git remote set-url --add --push gitee https://github.com/你的用户名/shiyu_app.git
> ```
>
> 之后只需 `git push gitee master` 就会同时推到两个平台。

## 六、常见问题（FAQ）

### Q1：提示 `fatal: not a git repository`？

说明当前目录不对。先确认你在项目目录里：`cd D:\project\deepseekcoding\Notebookproject\shiyu_app`，
再看一眼有没有 `.git` 文件夹（我帮你初始化好了，应该有的）。

### Q2：提示 `remote origin already exists`？

说明已经添加过远程地址。用 `git remote -v` 查看已有哪些，
或者直接重新设置：`git remote set-url origin 新地址`。

### Q3：GitHub/Gitee 要的"密码"到底是什么？（重要）

GitHub 和 Gitee **不允许用登录密码推代码**，要用**私人令牌（Personal Access Token）**：

- **GitHub**：头像 → Settings → Developer settings → Personal access tokens →
  Tokens (classic) → Generate new token → 勾选 `repo` → 生成 → **复制保存**（只显示一次！）
  推送时用户名填你的 GitHub 用户名，密码粘贴这个令牌。
- **Gitee**：头像 → 设置 → 安全设置 → 私人令牌 → 生成新令牌 → 勾选 `projects` → 提交 → **复制保存**

### Q4：推代码时让输入用户名密码，每次都输好麻烦？

Windows 上配置凭据管理器（只输一次，以后自动记住）：

```bash
git config --global credential.helper manager
```

下次推送时输一次，之后就会自动保存。

### Q5：`error: failed to push some refs`？

一般是仓库里已经有别人（或之前测试）的文件，本地和远程不一致。
如果你确定远程仓库是空的（创建时没勾选任何初始化选项），可以强制推送：

```bash
git push -u gitee master --force
```

> ⚠️ `--force` 会覆盖远程内容，只在确认远程是空仓库时使用。

### Q6：Gitee 推送很慢或失败？

国内访问 GitHub 慢是正常的，Gitee 一般没问题。如果 GitHub 连不上，
可以试：
- 换个时间段再试
- 配置代理（有梯子的话）
- 用 SSH 方式（见 Q7）

### Q7：有没有更安全的 SSH 方式？

SSH 免密码、更安全，但配置稍复杂：

1. 生成密钥：`ssh-keygen -t ed25519 -C "你的邮箱"`（一路回车）
2. 查看公钥：`cat ~/.ssh/id_ed25519.pub`（复制全部内容）
3. GitHub：Settings → SSH and GPG keys → New SSH key → 粘贴 → 保存
   Gitee：设置 → SSH 公钥 → 粘贴 → 保存
4. 把远程地址换成 SSH 形式：
   ```bash
   git remote set-url gitee git@gitee.com:你的用户名/shiyu_app.git
   git remote set-url github git@github.com:你的用户名/shiyu_app.git
   ```

### Q8：要不要加 LICENSE（开源许可证）？

**建议加**。许可证告诉别人"可以怎么用你的代码"。

- **MIT**：最宽松，别人随便用，只要保留版权声明。适合个人项目
- **Apache-2.0**：类似 MIT，额外包含专利授权，很多大厂项目用
- **GPL-3.0**：别人必须同样开源，传染性强

小白推荐 **MIT**。加的方法：在仓库页面新建一个名为 `LICENSE` 的文件，
GitHub/Gitee 都有现成模板可以选择。

### Q9：素材版权有问题吗？

- 段位插画：你已获得授权 ✅
- 白噪音音频：如果也是你自己录制/购买的素材，需确认授权允许公开分发；
  如果是网上下载的免费音效，注意看它的许可证是否允许商用/再分发。

> 💡 稳妥做法：在 README 里注明素材来源与授权情况。

### Q10：开源了别人能偷我的创意吗？

代码开源意味着任何人都能复制。如果你在意，可以：
- 不公开（私有仓库）——但那就不叫开源了
- 开源但选严格一点的许可证（如 GPL）
- 接受现实：创意不值钱，**持续迭代的能力**才值钱。开源反而能帮你积累口碑和 star

## 七、开源之后还能做什么

1. **写一个好 README**：我已经帮你写好了项目介绍（功能、技术栈、运行方法），
   你可以在 README 里补充几张 App 截图，效果更好
2. **发到社区**：把 Gitee/GitHub 链接发到 V2EX、掘金、知乎、小红书，让更多人看到
3. **持续更新**：每次修 bug、加功能，commit + push，让项目保持活跃
4. **收集反馈**：开 Issues（问题反馈），看别人提的 bug 和建议，这也是成长
